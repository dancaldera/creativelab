The **Status** column is meant to be trusted: anything not fully implemented says so, and
links to the issue that tracks it.

Legend: ✅ implemented · ⚠️ partial, with the gap named · ❌ not implemented (post-MVP)

## Verification entry points

```bash
pnpm verify         # typecheck + lint + every unit/integration test (654 tests, 30 files)
pnpm e2e            # the asserted brief-to-export journey (produces a real MP4)
pnpm backlog:plan   # the PRD-derived issue graph, without touching GitHub
```

Current state at the time of writing: `pnpm typecheck` clean across all six projects,
`eslint .` exits 0 with no errors or warnings, **654 tests pass in 30 files**, the webview
bundles cleanly, `pnpm e2e` passes all 52 asserted checks with the exported file
independently re-probed, and the Rust host builds and tests under `cargo test`.

The assertions in `pnpm e2e` are the ones that matter most: they exercise the same
packages the desktop app does, with no window and no network, and they check the _output
file_ rather than the code's opinion of it.
